# 📜 Правила та Стандарти Розробки EnergySavior (Development Standards & Rules)

Цей документ є головним обов'язковим кодексом стандартів розробки для проекту **EnergySavior**. Усі зміни в кодовій базі, модулях та документації повинні суворо відповідати цим нормам.

---

## 🏛️ 1. Мовний стандарт проекту (Language & Localization Standard)
1. **Інтерфейс користувача (GUI & Tray):** 100% українською мовою (назви кнопок, картки, підказки, діалоги, повідомлення у треї).
2. **Коментарі в коді (Code Comments & Docstrings):** Пишуться виключно українською мовою для забезпечення єдиної стилістики та прозорості архітектури.
3. **Логування подій (Log Messages):** Усі повідомлення подій ядра, інтерфейсу та апаратних контролерів пишуться українською мовою із чіткими категоріями модулів (`[Інтерфейс]`, `[Телеметрія]`, `[Профіль]`, `[Відеокарта]`, `[Дисплей]`, `[Охолодження]`, `[WindowsPower]`, `[Конфігурація]`).
4. **Документація проекту:** Файли `DEVELOPMENT.md`, `README.md`, `CHANGELOG.md` та правила розробки ведуться українською мовою.

---

## ⚡ 2. Стандарт швидкодії: Нульове блокування UI (Zero-Lag UI Rule)
1. **Категорична заборона важких операцій у потоці вікна:** У функціях `WndProc`, `WM_PAINT`, `WM_LBUTTONDOWN`, `WM_MOUSEMOVE` заборонено викликати блокуючі системні виклики (`system()`, `_popen()`, синхронний запуск PowerShell, повільне читання з диска).
2. **Фоновий воркер телеметрії:** Усі опитування датчиків заліза (акумулятор, процесор, NVML GPU, WMI) виконуються виключно в потоці `TelemetryThread::WorkerLoop()` з фіксованим інтервалом (1.5 с).
3. **Швидкість рендерингу 0.0 мс:** Функція `GuiWindow::Paint()` лише зчитує готовий кешований знімок `TelemetryThread::GetData()` через швидкий м'ютекс і малює вікно. Жодного опитування заліза під час малювання!
4. **Запобігання брязкоту (Debounce):** Швидкі натискання на кнопки профілів або перемикачів повинні блокуватися атомарним прапорцем `std::atomic<bool> s_isSwitching`.

---

## 🔒 3. Багатопотокова безпека (Thread Safety)
1. Спільний стан між потоком вікна та фоновим воркером (`s_data`) повинен бути захищений `std::mutex` через RAII `std::lock_guard<std::mutex> lock(s_mutex);`.
2. Фоновий запуск зовнішніх допоміжних скриптів WMI виконується у відокремленому потоці (`std::thread(...).detach()`) з прихованим вікном процесу (`CREATE_NO_WINDOW`, `SW_HIDE`).

---

## 📝 4. Стандарти Системи Логування (Logging Standards)
1. **Обов'язковість реєстрації дій:** Будь-яка дія користувача (перемикання вкладки, клік по кнопці, зміна налаштування) та будь-яка апаратна подія (зміна джерела живлення, зупинка процесу на GPU, зміна оверлею Windows Power) **повинна реєструватися в журналі**.
2. **Структура запису логу:**
   `[РРРР-ММ-ДД ГГ:ХХ:СС.ммм] [РІВЕНЬ] [МОДУЛЬ] Текст повідомлення українською мовою`
33. **Рівні логування:**
   - `INFO`: Нормальна робота, зміна режимів, кліки користувача, фонові оновлення.
   - `WARN`: Нештатні, але не критичні ситуації (повторні спроби, fallback схеми).
   - `ERROR`: Помилки доступу до заліза, збої створення процесів, помилки оновлень.
   - `DEBUG`: Деталі внутрішніх обчислень для налагодження.
4. **Ротація та збереження:** Лог-файл зберігається у `%LOCALAPPDATA%\EnergySavior\energy_savior.log` з ротацією на 2 МБ. фоновим воркером (`s_data`) повинен бути захищений `std::mutex` через RAII `std::lock_guard<std::mutex> lock(s_mutex);`.
2. Фоновий запуск зовнішніх допоміжних скриптів WMI виконується у відокремленому потоці (`std::thread(...).detach()`) з прихованим вікном процесу (`CREATE_NO_WINDOW`, `SW_HIDE`).

---

## 🎨 5. Стандарти Графічного Інтерфейсу (GDI+ UI & Layout)
1. **Вкладкова організація (Tab Navigation):**
   - **⚡ Головна (Dashboard):** Оглядова панель швидкого контролю без зайвого захаращення.
   - **📈 Графіки та моніторинг (Graphs):** Великий розгорнутий графік споживання потужності в реальному часі (60 секунд історії) та детальні параметри акумулятора/TDP.
   - **💻 Процеси та пристрої (Devices):** Повний список процесів на дискретній відеокарті з можливістю індивідуального завершення за PID, а також таблиця апаратних пристроїв ноутбука.
2. **Чистота верстки (No Overlapping):**
   - Елементи ніколи не повинні накладатися один на одного або обрізатися при зміні системного масштабування.
   - Кожна мітка, значення та кнопка має чітко розраховані межі (`Rect`).
3. **Обробка перетягування вікна:**
   - Натискання на інтерактивні елементи керування (кнопки, вкладки, тумблери) мають абсолютний пріоритет.
   - Перетягування вікна за заголовок дозволяється **тільки** у вільних від кнопок зонах заголовка (`y < 46` та поза межами кнопок).
4. **Подвійна буферизація:** Рендеринг ведеться виключно у сумісний контекст пам'яті (`CreateCompatibleBitmap`) з фінальним копіюванням через `BitBlt` для усунення мерехтіння.
5. **Колірна палітра та естетика:**
   - Темна тема: фон `#0d1117`, картки `#161b22`, рамки `#30363d`.
   - Акценти: Неоновий ціан `#00e5ff`, смарагдовий зелений `#00e676`, кораловий червоний `#ff1744`, бурштиновий `#eab308`.

## 🏷️ 6. Стандарт Версіонування CalVer (Calendar Versioning)
1. **Єдиний формат версій:** `<стадія>-<рік>.<місяць>[.<патч>]` (наприклад: `alpha-2026.10`).
2. До публічного відкриття основного релізу стадія позначається як `alpha` або `beta`.
3. Усі бінарні релізи та автооновлення перевіряють версії за допомогою парсера `UpdateManager::ParseVersion()`.

---

## 🧪 7. Стандарт Контролю Якості та Тестування (Automated QA)
1. Перед будь-яким релізом чи комітом **усі 21+ юніт-тестів повинні проходити на 100%** за допомогою команди:
   ```cmd
   build.bat test
   ```
2. Будь-який новий функціонал повинен супроводжуватися відповідними тестовими кейсами у `tests/TestMain.cpp`.

## 🌐 8. Стандарт Локалізації, Кодування та Цілісності Інтерфейсу (UI Text, Icons & UTF-8 Integrity)
1. **Обов'язковий UTF-8 BOM:**
   - Усі вихідні файли коду (`.cpp`, `.hpp`, `.h`, `.rc`) повинні зберігатися виключно у кодуванні **UTF-8 з BOM** (`\xEF\xBB\xBF`).
   - Це усуває небезпеку того, що компілятор GCC на Windows інтерпретуватиме кирилицю чи символи через застарілу системну кодову сторінку CP-1251.
2. **Запобігання подвійному перекодуванню (Mojibake Prevention):**
   - Категорично заборонено редагувати або перезберігати файли за допомогою PowerShell або batch-файлів без явного зазначення кодування `utf-8-sig`. Утиліти маніпуляції кодом повинні використовувати Python з `encoding='utf-8-sig'`.
   - Заборонено вставляти не-ASCII символи безпосередньо в однорядкові команди CLI PowerShell `-Command "..."`, оскільки оболонка спотворює їх перед передачею.
3. **Стандарти інтерфейсу та іконок:**
   - **Брендинг:** Заголовок вікна завжди повинен бути `ENERGY SAVIOR`.
   - **Віконні кнопки:** Кнопка згортання — символ `—` (U+2014 em-dash), кнопка закриття у трей — `✕` (U+2715 multiplication X).
   - **Навігаційні вкладки:**
     - `⚡ Головна` (Dashboard, id 100)
     - `📈 Графіки та моніторинг` (Graphs, id 101)
     - `🎮 Процеси та пристрої` (Devices, id 102)
   - **Кнопки режимів:** `[ ECO ]\n60Hz + Quiet`, `[ MAX ]\n144Hz + Boost`.
   - **Захист від накладання:** Розміри карток, текстових написів і кнопок колонтитула (зокрема кнопки `[Оновлення]` та підказки в треї) мають строго розраховані координати з відстанню не менше 30 пікселів між ними.
4. **Обов'язкові автоматичні тести:**
   - Будь-яка збірка обов'язково валідує інтерфейс через тести `Ui_GuiButtonsAndSymbolsIntegrity`, `Ui_HardwareStringsLocalizationIntegrity` та `Ui_SourceFilesUtf8BomIntegrity` у `tests/TestMain.cpp`.
